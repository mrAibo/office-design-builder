# Post-v0.1.0 Development Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` or `executing-plans` to implement this plan task-by-task. Every behavior change uses a focused RED -> GREEN cycle.

**Goal:** Harden the published CLI first, then expand platform coverage, distribution, rendering, inspection, and Office formats without weakening determinism or editability.

**Architecture:** Keep versioned contracts in `models.py`, stable public failures in `errors.py` and `cli.py`, and format-specific work in focused inspector or renderer modules. Complete and commit each task independently. Later feature work must not start while an earlier hardening gate is red.

**Tech stack:** Python 3.12, dataclasses, Pillow, python-pptx, pytest, setuptools, uv, GitHub Actions, LibreOffice for optional visual acceptance.

**Spec:** `docs/plans/2026-09-20-office-design-builder-design.md`

## Global constraints

- Use strict test-driven development: observe each focused test fail before implementation.
- Keep identical input output byte-identical.
- Preserve native Office editability; never replace slides with screenshots.
- Do not add network requirements to tests or builds.
- CLI failures must use stable identifiers and non-zero exit codes.
- Do not publish to PyPI, create credentials, or alter repository secrets without explicit confirmation.
- Run `pytest -q`, offline build, CLI help, example build/verify, and `git diff --check` before every task commit.
